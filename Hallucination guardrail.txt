E-Commerce Chatbot & Hallucination Guardrail – Complete Single Document
Purpose

This document defines what data should be used for an e-commerce chatbot and what data must be stored in the vector database used for hallucination detection. It clearly separates conversational behavior from factual truth and explains how both systems work together safely.

Core Principle

The chatbot dataset and the vector database serve different purposes and must not be mixed blindly.

The chatbot dataset or system prompt exists to define how the chatbot behaves, speaks, and guides users.

The vector database exists to define what is factually true and allowed to be stated by the chatbot.
Only authoritative, stable, and verifiable information belongs in the vector database.

If a statement cannot be verified from the vector database, it must be considered unsupported and treated as a potential hallucination.

Data That MUST Be Stored in the Vector Database (Source of Truth)

The vector database must contain only stable platform facts and policies that do not change frequently.

Platform Scope and Product Boundaries

The platform sells products across categories such as clothing, footwear, electronics, home essentials, and daily-use items. Product availability depends on stock, size, color, and delivery location. Prices and offers may change and are always shown on the product page. The chatbot must not claim fixed prices or permanent offers.

Order and Checkout Policy

Users must have a registered account to place orders. Orders are placed by selecting products, adding them to the cart, and completing checkout. Users can review, update, or remove items from the cart before placing an order. Every order generates a unique order ID used for tracking and support.

Delivery and Tracking Policy

Standard delivery time is estimated between three to seven business days. Delivery timelines are estimates and not guaranteed. Delivery depends on logistics and user location. Order status can be tracked using the order ID available in the user account. The chatbot must not promise exact delivery dates or times.

Payment and Security Policy

Supported payment methods include credit cards, debit cards, UPI, net banking, and digital wallets. Cash on delivery is available only for selected locations. All online payments are processed using encrypted payment gateways. The platform never asks users to share OTPs, CVV numbers, card details, or passwords through chat.

Return and Refund Policy

Most products are eligible for return within seven days of delivery, subject to return conditions. Returned items are inspected before refund approval. Refunds are processed within five to seven business days after approval. Refunds are issued to the original payment method. The chatbot must not guarantee instant refunds.

Customer Support and Escalation Rules

Customer support is available via chat, email, and phone. The chatbot is the first point of contact and should resolve common issues. Complex or unresolved issues are escalated to human support. Support availability may vary.

Chatbot Safety and Guardrails

The chatbot must not fabricate information or make assumptions when data is missing. The chatbot must not promise guaranteed outcomes such as exact delivery dates, instant refunds, or permanent discounts. The chatbot must not request or accept sensitive personal or payment information. The chatbot must ask for clarification when it does not have enough information to respond accurately.

Data That MUST NOT Be Stored in the Vector Database

The vector database must not contain greetings, friendly conversation text, example replies, marketing language, dynamic pricing, live stock data, subjective claims, or tone-based content. These elements belong only in the chatbot’s conversational dataset or system prompt.

Data Used for Chatbot Behavior (Separate from Vector DB)

The chatbot dataset or system prompt defines tone, friendliness, response style, default guidance, and conversation flow. This includes greetings, polite closings, example interactions, and user-friendly explanations. These elements help the chatbot communicate well but are not used for factual validation.

Default User Entry Intent Awareness

The chatbot must always be able to respond clearly and accurately to these common user intents:

What products do you sell
How can I place an order
Where is my order
How can I contact support

The chatbot should infer answers for these intents strictly from the factual information defined in this document.

Hallucination Guardrail Configuration Guidance

The hallucination detection guardrail validates chatbot responses against the vector database using file search.

Recommended configuration for an e-commerce platform:

Model: gpt-4.1-mini

Confidence threshold: 0.7 (increase to 0.8–0.9 to reduce false positives)

Knowledge source: vector store containing only the documents described above

If a chatbot response contains a claim that is contradicted or unsupported by the vector database, the guardrail should flag it and block or rewrite the response.

Final Takeaway

The vector database is the single source of truth.
The chatbot dataset defines how to talk, not what is true.

Never mix conversational text with factual policy data in the vector database.
Clean, authoritative, and concise documents result in better hallucination detection, lower latency, and higher trust.
